# 研发流程与环境

本轮不执行以下开发动作；本文件供后续团队开工使用。

## 环境

本地仅用合成数据和独立存储前缀；预发布模拟生产拓扑但使用测试邮箱与私有测试桶；生产只由发布流程更新。数据库、对象存储、邮件发送域名与凭据不能混用。测试任务不得向真实客户发邮件。

环境清单需登记应用地址、运行时版本、数据库版本、文件域名、邮件服务、队列轮询与租约、扫描器限制、备份策略、日志保留和责任人。密钥只登记名称及存储位置，不登记值。

## 开工顺序

T01 验证 Python/Django/DRF 与 PostgreSQL 兼容；锁定依赖和镜像摘要；确定前端和后端的格式、静态检查工具；建立合成数据集和最小 CI。版本选择按官方维护状态复核，不写“永远用最新版”。

T01 另须执行 [文件写入与回收协议](07_文件写入与回收协议.md) 的真实存储验证：覆盖响应丢失、执行者永久失联与延迟写入，取得独立终结证据。不能取得证据时该路径不冻结、不放行 B03；由总负责人组织适配方案修订。文字审校通过不能替代本项。

公共契约先经前端、后端、测试共同评审；T01-C交付并冻结正式API模式，客户端类型在对应前端任务消费已冻结模式生成。当前仍只有文字设计，不把模式生成推迟到各模块自行开工之后。模型改动必须附迁移说明，包含旧版本兼容期和恢复策略。具体待决问题与退出证据见[T01待决项与冻结清单](../11_开发启动包/08_T01待决项与冻结清单.md)。

v1.3 [开发启动包](../11_开发启动包/01_启动顺序与交接边界.md)提供文字字段样例、统一合成数据及16张首批任务卡；[技术风险方案](../10_技术风险验证方案/01_实验清单与放行门槛.md)把T01取证、Q阶段产品测试和O阶段恢复分别定义。两者均是未执行的准备成果，不代替正式模式冻结、GATE-A或运行证据。

## 一个任务的流转

READY：任务卡输入齐备、依赖满足 → IN_PROGRESS：单一责任人实施 → REVIEW：提交变更和验证证据 → TESTING：测试按验收场景验证 → DONE：证据、文档和交接完整。无法继续标 BLOCKED，写阻塞对象和解除条件，不把等待时间算作实现完成。

分支按任务 ID 命名；每个变更集围绕一个可审查目的。评审关注用户行为、权限/状态、数据迁移、失败处理及必要测试。不把大规模格式变更混入业务逻辑。公共接口变更需消费者参与评审。

## 必需检查

常规变更：格式、类型/静态检查及相关单元测试。身份、发布、决定、删除变更：真实 PostgreSQL 集成测试和跨租户/并发回归。页面主流程变更：浏览器端到端和移动尺寸检查。部署变更：预发布恢复/回滚演练。低风险文案修改不强行新增与实现重复的测试。

持续集成产物包含唯一构建版本、依赖锁定、测试结果及镜像摘要；预发布通过后把同一个产物提升到生产，不在生产重新临时构建。禁止用空测试、跳过失败或改变断言来掩盖问题。

## 数据迁移

默认使用扩展—切换—收缩：先加兼容字段，部署兼容读写，迁移历史数据并核对，再在另一次发布移除旧字段。回滚应用通常不回滚已写入的业务数据；破坏性迁移需独立维护窗口与恢复方案。

## 完成定义

功能与异常均满足任务卡；测试可复现；日志不含敏感值；没有未登记契约变化；交接写明实际状态。测试证据链接必须可打开，不能只填“测试通过”。
