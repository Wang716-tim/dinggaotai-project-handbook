# 权限与安全

本项目处理客户未公开文件，权限与文件隔离属于核心产品正确性。这里是设计要求，尚未实施安全测试。

## 权限矩阵

| 操作 | Owner | Editor | 指定邮箱客户 | 运营管理员 |
|---|---|---|---|---|
| 查看空间全部项目 | 是 | 是 | 否，只能看授权版本 | 默认否 |
| 新项目、草稿、上传、发布、撤回 | 是 | 是 | 否 | 否 |
| 评论 | 审阅中 | 审阅中 | 本授权轮审阅中 | 否 |
| 确认／需要修改 | 否 | 否 | 是，限当前有效轮 | 否 |
| 内部记录导出 | 是 | 是 | 仅本轮只读记录 | 默认否 |
| 管理成员、请求删除 | 是 | 否 | 否 | 经支持流程处理特殊情况 |
| 开通空间、续期、冻结 | 否 | 否 | 否 | 是，逐次审计 |

成员可见空间全部项目是明确产品限制；若客户需要部门隔离，首版不适配，不用前端隐藏伪装项目级权限。

## 服务状态与动作

下表只授予服务状态允许的能力，仍须满足角色、项目、版本及授权约束；不得因状态表写“允许”绕过其他检查。

| 动作 | ACTIVE且未到期 | READ_ONLY或已经到期 | SUSPENDED／空间删除处理中 |
|---|---|---|---|
| 内部身份验证、/me状态页及待接受页 | 允许；待接受身份只有自身状态 | 允许；待接受身份仍无业务权限 | 只显示最小身份、状态及处理渠道，不读取配额或业务内容 |
| 内部及客户注销 | 允许；仅撤销当前会话 | 允许 | 允许，不要求分享或空间仍有效，不返回业务内容 |
| 客户验证、既有内容读取、客户下载签发 | 有效分享允许 | 有效既有分享允许只读验证及下载 | 拒绝 |
| 内部既有读取、附件下载签发及记录导出 | 允许 | 允许 | 默认拒绝，依法处理请求走受控支持流程 |
| 本人通知读取及标记已读 | 有效成员允许 | 有效成员允许；已读标记属于个人阅读状态 | 拒绝 |
| 业务新增与变更（新项目/草稿、元数据修改、上传及失败重试、发布、评论、决定、重发分享、新邀请、接受邀请、归档及归档恢复、普通草稿/附件删除） | 允许 | 拒绝；有效邀请也不能新增成员关系 | 拒绝 |
| 撤回审阅中版本、撤销分享、移除Editor、Owner请求项目删除 | 角色允许 | 角色允许，作为保护性动作 | 经受控支持流程执行 |
| 宽限期内撤回项目删除 | Owner允许 | Owner允许；恢复后仍只读 | 受控支持核验，不能绕过空间冻结 |
| 后台扫描及结算已接收内容 | 有效代际允许 | 可完成技术结算，但不能生成新业务决定或发布 | 停止对外发布，转受控处置 |
| 后台清理、过期回收、安全审计 | 独立系统权限 | 独立系统权限继续 | 独立系统权限继续，不依赖客户会话 |

写事务在工作空间锁内同时检查service_state和服务端当前时间相对expires_at；到期Worker只负责持久状态和提醒，不能成为唯一禁写开关。撤回删除仍依赖原宽限期及配额规则，续期不复活已撤销授权。

### API动作对照

下表覆盖当前 API 的每个动作类别；GET/PATCH 同一路径按方法分别判定。新增端点必须先归类，未归类默认拒绝。状态规则不影响无资格身份的中性响应与限流。

| API端点（均在 /api/v1 下） | 对应动作类别 |
|---|---|
| GET /auth/csrf；POST /auth/challenges、/auth/verify；GET /me | 内部身份验证及最小状态；待接受身份不返回成员配额和业务资料 |
| POST /auth/logout、/review/logout | 注销；会话已失效也幂等清除凭据，保持同源/CSRF防护 |
| POST /review/challenges、/review/verify | 客户验证；必须复核有效分享，冻结拒绝 |
| GET /members、/projects、/projects/{id}、/projects/{id}/versions、/versions/{id}、/uploads/{id}、/assets/{id}、/versions/{id}/comments、/versions/{id}/receipt、/versions/{id}/receipt/export | 内部既有读取/导出，仍按角色与删除状态过滤 |
| POST /assets/{id}/download | 内部附件下载签发；READY且满足该附件访问权限 |
| GET /review/version、/review/comments、/review/receipt；POST /review/assets/{id}/download | 客户既有读取/下载；仅当前授权版本 |
| GET /notifications；POST /notifications/{id}/read | 有效成员本人通知读取/已读 |
| POST /invitations、/invitations/accept | 新邀请或新增成员关系；只读拒绝接受，邀请有效期不因此延长 |
| POST /projects、/projects/{id}/versions、/projects/{id}/archive、/projects/{id}/restore、/versions/{id}/publish、/versions/{id}/shares、/versions/{id}/uploads、/assets/{id}/retry、/versions/{id}/comments、/review/comments、/review/decisions | 业务新增与变更 |
| PATCH /projects/{id}、/versions/{id}；PUT /uploads/{id}/content；DELETE /versions/{id}、/assets/{id} | 业务变更；用户发起失败文件重试也不等同于后台已有任务结算 |
| POST /versions/{id}/withdraw；DELETE /shares/{id}、/members/{id}、/projects/{id} | 保护性动作；撤回只限IN_REVIEW，移除/项目删除仅Owner，不能移除Owner |
| POST /projects/{id}/cancel-deletion | 宽限期内撤回项目删除；Owner；仍受原空间服务状态限制 |

有效邀请下的内部验证与邀请投递不等于接受邀请获准；成员关系真正建立时再次锁空间检查到期、席位、邮箱和邀请状态。内部OTP仅允许有效成员或仍有有效邀请的身份，客户OTP另依分享授权；被移除且无新有效邀请者不因旧登录记录重新取得资格。

## 每次请求的检查顺序

校验协议、同源与 CSRF → 解析可信身份 → 校验空间服务状态和成员有效性 → 查询限定空间的目标 → 校验项目/版本状态 → 校验动作权限 → 在写事务内再次检查可能变化的状态。客户业务请求还要检查授权未过期/撤销、会话未过期、版本与项目关系及当前发布指针。内外注销只执行本会话撤销和凭据清理，不要求业务授权仍有效；其他防跨站检查保留。

同空间也必须检查附件所属版本，不能凭知道 asset_id 访问其他轮次。内部接口和客户接口分别测试，客户 Cookie 不能通过内部认证。注销、移除成员、冻结空间均由服务器立即拒绝后续请求。

对于要求幂等键的写操作，上述顺序中的业务状态与 revision 判断只用于新执行：先验证当前身份、空间服务状态、对象范围和授权，再按 API 契约检查同键摘要与已提交结果；合法重放返回原结果，不因其已提交后形成的终态或旧 revision 而被拒绝。同键异内容返回409，未提交的新执行再校验当前业务状态和 revision。幂等重放不能绕过只读、撤销、删除或其他当前访问限制。

## 凭据与浏览器

内部和客户 Cookie 分开命名，Secure、HttpOnly、SameSite=Lax；不在 localStorage 保存分享密钥、验证码或会话。分享链接建议将密钥放 URL fragment，由客户端取出后用 POST 换取验证挑战，并清除地址中的密钥；页面不得加载第三方分析脚本。浏览器历史及转发仍可能泄露链接，应明确用户控制分享范围。

登录、验证码验证、客户决定和下载签发均有 CSRF 校验和 Origin 校验；不能假设 DRF 对自定义匿名端点自动完成所有保护。服务端错误和日志不回显凭据。使用框架维护中的实现，避免自创密码算法。[DRF 官方说明](https://www.django-rest-framework.org/api-guide/authentication/)。

## 文件防护

客户端类型检查只用于体验。后端同时检查扩展名、声明类型、魔数、大小和可接受文件结构，随机生成对象 key，显示文件名仅作为元数据。文件放私有隔离区，扫描成功后才变为 READY；扫描服务失效时保持不可读。

图片解码设像素、内存与时间限制，预览重编码并去除 EXIF 等非必要元数据；原件保留供交付，下载时提示包含原件元数据。PDF 不在应用同源内执行或嵌入；下载用附件响应与独立文件域名。对加密、扫描器无法判断或结构异常的 PDF 明确拒绝或标为失败，不承诺可安全审阅。

扫描器以低权限运行、禁出站网络、限制 CPU/内存/运行时间；病毒库更新走受控更新通道。拒绝 HTML、SVG、脚本和压缩包。原件不得上传公开恶意样本分析网站。策略参考 [OWASP 文件上传指南](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)。

下载 URL 由每次授权检查后签发，60 秒有效并禁止缓存，文件域名不携带应用 Cookie。签名网址在有效期内仍可转发，已下载内容无法远程召回。页面不能把“已撤销”解释成已追回所有文件。

## 运营与隔离

开通、续期、冻结的受控后台最小输入、角色边界、并发和审计验收见[受控运营操作规格](08_受控运营操作规格.md)。这是M01/R15文字设计；后台身份、首次Owner核验和字段模式仍待T01。冻结与空间删除处理中不通过普通续期恢复，特殊支持操作另审，不提供通用字段编辑绕过状态规则。

应用数据库账号不拥有管理员权限；迁移账号独立。对象存储凭据只授予所需桶和前缀；生产/预发布分开账号或权限边界。供应商密钥保存在密钥管理服务或受控环境，不进入文档和日志。运营后台只展示开通、到期、额度和任务状态；查看客户文件需客户授权及受控工单，保留访问记录。

上线前最少验证：跨租户 ID 遍历、旧客户会话、双窗口并发决定、脚本评论、文件伪装、超大图、验证码枚举、Cookie/CSRF、日志脱敏、备份访问。任何越权属于阻断缺陷。
