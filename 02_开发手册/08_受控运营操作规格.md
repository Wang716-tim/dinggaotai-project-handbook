# 受控运营操作规格

v1.5 · 2026-11-25。R15/B01的文字设计补充，用于T01评审和后续实施。当前没有运营后台、实际开通、续期或冻结记录；本页不授予执行任何真实操作的权限。具体入口、认证配置、字段模式、首次Owner核验及实测证据仍由T01冻结。公共业务API仍为原48项，不新增自助建空间或公开运营端点。

本页只展开[M01责任](../03_模块工作包/M01_账号与团队.md)。身份和隔离以[权限矩阵](03_权限与安全.md)为准；空间字段以[数据模型](01_数据模型.md#身份与配额)为准；业务状态与锁顺序以[状态机](../01_项目手册/05_业务流程与状态机.md)为准。重大权限扩张、套餐或预算改变仍须单独决策。

## 操作人、目标与可见范围

运营身份与Owner、Editor、客户分开授权；有内部账号不等于有运营权限。运营只能处理受控工单所指向的工作空间，不得通过修改ID、隐藏字段或通用数据编辑器扩大到任意对象。后台使用现有服务的状态/配额检查入口，不能直接修改业务表绕开规则。

运营摘要仅含定位与状态所需的空间ID/名称、脱敏Owner信息、服务状态、到期时间、revision、额度和占用汇总、操作结果/审计引用。运营摘要的权限与普通用户的`/me`响应不同，不能通过扩大`/me`让冻结空间身份读取业务汇总。默认不可看项目正文、附件内容、评论、决定快照、文件下载地址或导出客户记录；特殊支持访问另走既有授权流程，不因拥有本页三项操作而获得权限。

每项操作都需明确已认证的操作人、目标、原因和受控工单/核验依据。T01冻结后台入口隔离、身份认证与会话失效、同源/CSRF、角色配置及审计访问方案；正式配置未完成不准接入真实空间。只授予三项明确动作，不能把框架默认全表增删改当作已验收的后台。

## 三项操作的业务契约

OP编号是评审定位，不是新HTTP端点或已实现错误码。字段列是逻辑输入，传输格式和存储映射由T01确认。

| 操作 | 最小逻辑输入与前置 | 事务结果与明确限制 |
|---|---|---|
| OP01 开通试点空间 | 经核验的首次Owner身份引用、空间名称、明确的UTC到期时间、操作请求标识、原因和受控核验引用；该账号尚无有效空间，未与另一次开通冲突 | 创建空间及唯一Owner关系，按原试点限制设置5席、20活跃项目、10GiB，写审计并共同提交；不能靠重复提交建立第二空间，不自动声称邮件送达或付费成功 |
| OP02 续期 | 目标workspace_id、预期revision、**新的绝对UTC到期时间**、操作请求标识、原因和业务依据；目标为ACTIVE或READ_ONLY，且新时间晚于当前到期时间及服务器当前时间 | 空间锁内重新核对状态/revision，延长有效期并递增revision；此前仅因到期只读且原因可核实的空间可恢复ACTIVE；保持成员、文件、历史决定、配额及占用不变。不得重建旧分享/客户会话，也不得将已过期授权重新变为有效 |
| OP03 冻结 | 目标workspace_id、预期revision、操作请求标识、原因和处置引用；目标为ACTIVE或READ_ONLY；同一冻结结果可读回 | 空间锁内设置SUSPENDED，递增revision并写审计；提交后每个业务请求立即按冻结规则拒绝，不等待Worker。已有决定不回滚，内外注销仍可完成，后台清理独立继续；不能把冻结解释为删除文件或撤回已下载内容 |

OP01首次Owner必须已完成T01选定的受控身份核验，核验依据与绑定对象匹配。普通邀请只产生Editor，不能把`role=Owner`塞入现有邀请请求。核验方式尚未确定时，开通链路保持待冻结；不能仅凭一封转发邮件或输入一个邮箱宣称身份已证实。新身份的创建/验证/绑定顺序、唯一Owner和一个账号一个有效空间的并发约束，须作为T01/B01验收内容。

首次开通时尚无workspace_id，操作归属先绑定已核验的首次Owner身份/核验引用与输入摘要，成功提交后再关联新空间ID及结果。首次身份级并发锁、唯一约束、幂等和审计载体由T01一起冻结；不得用客户端随填的空间ID作为可信归属。不同操作标识并发开通也须由一个账号一个有效空间的约束阻止重复。

OP02以明确到期时间代替“加30天”等可被重复执行累加的指令。SUSPENDED和DELETION_PENDING不适用普通续期，不因收款、改时间或Worker运行自动恢复。冻结原因解除、身份变更、Owner转让、特殊额度调整及空间删除撤回均不包含在这三项操作中；需要时按受控支持与既有决策流程评审，不能临时开放通用字段编辑。项目删除中的对象也不会因空间续期自动复原。

当前Workspace字段没有单独的只读原因字段。T01须冻结“仅因到期只读”的可验证判据和证据来源；不能只看到READ_ONLY就推断可恢复ACTIVE。原因无法确认时，不执行恢复写能力的续期，先交受控核查；若需要新增模型字段，须由总负责人评审并同步迁移/契约，不能由运营页面自行推断。

OP03和正在进行的决定、发布或评论共享空间锁：业务先提交则保留真实结果，冻结先提交则后续写入拒绝。签发过且尚未到期的60秒文件URL和已下载文件仍有既定限制，不能宣传冻结能远程召回。

## 提交、冲突与未知结果

后台先展示目标摘要、当前状态/到期时间、拟变更值和影响，再由操作人确认。确认前后均校验运营身份和目标权限；仅有前端按钮禁用不构成保护。当前授权与目标范围校验后，先核对同标识的输入摘要及已提交的安全结果，合法重放不因原请求携带旧revision被拒绝；只有首次执行才核对当前revision、状态及业务前置。事务内的空间变更、revision和AuditEvent一起提交，审计写入失败时不能留下未审计的成功业务变更。

同一操作请求标识只表示同一意图，必须绑定操作人、动作、目标和输入摘要；相同标识改内容应拒绝。其保存位置、生命周期和原结果读取入口由T01冻结，可复用既有幂等模式但不得凭空宣称新增端点已可用。查询结果仍须校验当前运营权限，不允许从历史结果绕过已撤销权限。

| 情形 | 页面/操作人处理 | 后端必须保证的结果 |
|---|---|---|
| 操作失败且事务未提交 | 显示可核对的原因与请求标识，重新核对后再操作 | 空间、Owner关系、到期时间与成功审计均不出现部分提交 |
| 两人同时续期或续期与冻结竞争 | 冲突后刷新目标摘要并人工确认，不静默换revision | 按空间锁/输入版本形成确定顺序；冻结不能被稍后到达的过期续期请求覆盖 |
| 提交后响应丢失 | 显示“结果待核实”，优先读取绑定该操作标识的审计/安全结果，再核对当前目标状态；当前状态符合预期不证明是本次操作提交 | 不自动发第二次开通，不再次累加有效期；结果无法判明时暂停该意图并交受控核查 |
| 已经SUSPENDED再发冻结 | 核实当前冻结和原操作结果，说明“已冻结” | 不生成重复冻结副作用或重复成功事件；新的不同处置原因可另记尝试审计，不伪装为再次状态变更 |
| 运营身份失效或目标越权 | 停止请求，清理受限页面数据 | 不提供历史结果或空间摘要，操作不执行 |

未确定的传输细节留在[T01冻结清单](../11_开发启动包/08_T01待决项与冻结清单.md)。请求标识的存在、审计尝试或界面提示都不能替代实际事务成功证据。

## 审计记录与事故处置

AuditEvent沿用现有actor_kind/actor_id、action、target_kind/target_id、request_id和safe_metadata。至少能关联实际操作人、受控工单编号、动作、目标空间、发生时间、变更前后状态/到期时间/revision及最终判定。具体动作枚举和safe_metadata字段在T01冻结，不把未实现名称写成现有接口约定。

失败/拒绝/无变更尝试通过受控安全日志记录；它们不能被计作成功业务变更。业务成功审计必须与变更同事务。后台不提供普通业务用户编辑/删除审计入口；权限与备份可复核不等于具有司法存证或绝对防篡改能力。

原因填写工单编号和必要说明，不附真实客户文件、验证码、完整邀请/分享链接、密钥、原始身份证明或付款截图；这些材料若确有必要，由获授权的人在受控位置保存。本公开文档仓库只保留设计、空表和脱敏引用，不接收这些证据原件。涉及邮箱时按数据模型规则规范化，运营列表和日志使用脱敏展示。

若错误开通、错误续期或误冻结，先停受影响操作，保留原审计并核查当前权限与并发结果；不能删除审计或通过改数据库掩盖。修复按受控工单留下新动作和理由，重大权限变化由总负责人评审。当前未定义的“解冻”不得当作通用撤销按钮上线。

## 待执行的验收分支

以下是已有A20-a/A21/A31以及身份/并发断言的操作侧细化；全部未执行，不额外修改P0预算。使用隔离环境、合成空间与测试身份，不接触真实客户。

| 分支 | 要构造的条件 | 必须采集的证据 |
|---|---|---|
| OP-T01 | 无运营权限的Owner、Editor、客户及已失效运营会话 | 每次被拒、无目标摘要泄露、无业务变更 |
| OP-T02 | 首次Owner核验缺失、账号已有有效空间、两次并发开通 | 缺核验不创建、最多一空间/唯一Owner、审计与关系一致 |
| OP-T03 | 正常开通与审计写入失败 | 配额符合G02；失败无孤立空间或部分成员关系 |
| OP-T04 | 已到期但Worker未运行，合法续期后再读写 | 到期时立即只读，续期后按新时间恢复适用能力；旧分享/会话不复活 |
| OP-T05 | SUSPENDED/DELETION_PENDING续期、伪造更高配额或Owner字段 | 普通续期拒绝；未授权字段不得改变状态、配额或身份 |
| OP-T06 | 续期与冻结并发、旧revision提交 | 两种实际时序与事务结果；冻结不被旧续期覆盖 |
| OP-T07 | 冻结与决定/发布/评论并发 | 先提交的合法结果保留，冻结后无新业务写；审计与最终状态对应 |
| OP-T08 | 冻结后读取、注销、文件清理与已有签名链接 | 业务读取被拒、注销可用、清理继续；签名有效窗口按G11解释 |
| OP-T09 | 同意图重复提交、同标识改内容、响应丢失 | 唯一业务结果；不同内容拒绝；当前有权才可核实结果；无重复成功事件 |
| OP-T10 | 运营尝试查看文件/记录或编辑审计、日志脱敏检查 | 默认不读业务内容；不得获得文件URL、密钥或原始身份证明；审计变更权限受限 |
