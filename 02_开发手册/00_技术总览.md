# 技术总览

状态：实现前设计基线；本轮不创建代码、依赖锁文件或部署配置。

## 架构选择

浏览器 → HTTPS 反向代理 → Vue 静态页面及同源 Django API → PostgreSQL 与私有对象存储。独立 Worker 进程从数据库领取扫描、通知、清理任务；扫描器运行于受限环境。Web 与 Worker 使用同一版本的业务应用，但可分别重启和扩容。

采用模块化单体：身份、项目、文件、审阅、决定、通知各自维护服务入口，共用事务数据库。避免把需要原子提交的发布和决定拆成跨网络事务。模块依赖在文档中明确，不能通过“直接改别人的表”绕开领域规则。

## 技术清单与取舍

| 层 | 建议基线 | 原因与限制 |
|---|---|---|
| 前端 | Vue 3、TypeScript、Vite | 团队工作台与响应式客户页；SPA 不承担复杂搜索引擎优化 |
| 后端 | Python 3.12、Django 5.2 LTS、DRF 兼容版本 | 使用成熟会话、校验、迁移和后台；开工时锁定经验证的补丁组合 |
| 数据 | PostgreSQL 17 最新可用维护补丁 | 唯一约束、事务和行锁；云服务可用性另核验 |
| 文件 | 阿里云 OSS 私有桶、独立文件域名 | 应用代理上传、短时授权下载；不自建分布式存储 |
| 文件处理 | 受限 Worker、ClamAV 类本地扫描器、维护中的图片处理库 | 原件不发送公共扫描网站；实际扫描器与资源限制需技术验证 |
| 任务 | PostgreSQL 持久任务表 + 事务 outbox | 降低中间件数量；需实现租约、重试、死信与幂等 |
| 部署 | Linux 容器、反向代理、托管数据库 | 便于一致部署；初期单区，明确存在应用单点 |
| 验证 | 后端集成测试、浏览器端到端测试、专项压测 | 以状态与权限风险驱动，不以覆盖率数字替代 |

选择依据：Django 支持期限、PostgreSQL 事务能力及 Vue 使用方式均已核验官方文档，见 [来源表](../01_项目手册/02_调研证据与假设.md)。具体框架小版本、镜像和扫描器尚未安装验证，T01 必须形成兼容性清单。

## 主要架构决策

ADR-01：同源部署与服务端会话，避免浏览器长期保存访问令牌。ADR-02：文件上传经过后端流式转发，换取配额、校验和路径控制；大文件吞吐不足时再评估直传。ADR-03：发布版本不可变，业务变更通过新版本。ADR-04：客户确认绑定验证邮箱，不宣称实名。ADR-05：首版结构化导出与浏览器打印，不部署服务端 PDF 渲染器。

替代方案：全栈单一语言可减少语言切换，但团队技能未知，无法认定更优；微服务、Kubernetes、向量数据库及模型 API 均没有首版必要性。若团队熟悉另一成熟框架，可在 T01 变更选型，必须保留数据和状态契约。

## 容量与扩展触发

初始验证负载为 50 活跃团队和 20 并发非上传请求，不承诺百万用户。扫描排队 p95 超过 60 秒时先检查任务积压及资源，再增加 Worker；数据库任务积压或锁争用长期影响业务时再评估专用队列；单实例可用性不足时部署第二实例。升级由实测指标触发。

开发目录将按前端、后端领域、契约、测试、部署分区；这是后续目录建议，本轮不建立空代码工程。共用文档保留于当前文件夹，不把生产凭据纳入仓库。
