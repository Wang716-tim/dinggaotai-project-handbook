# 观测与指标

技术观测负责可恢复，产品指标负责判断是否值得继续。采集最少必要数据，不把文件名、评论正文、客户邮箱或分享密钥发给分析平台。

## 产品指标定义

| 指标 | 分子／分母与窗口 | 数据来源 |
|---|---|---|
| 每周完成决定项目数 | 自然周内产生至少一次客户决定的不同项目数 | Decision，按 workspace 去重汇总 |
| 首次发布成功率 | 开通后7天内首次发布的空间 / 已观察满7天且有交付机会的试点空间 | Workspace、Version及运营记录 |
| 首次闭环率 | 首次发布后14天内有客户决定的空间 / 已观察满14天的首次发布空间 | Version、Decision |
| 第二项目复用率 | 首次闭环后14天内发布第二个不同项目的空间 / 有第二项目机会且观察满14天的空间 | 业务表加运营资格记录 |
| 付费转化 | 实际到账团队 / 已获得明确报价且观察满14天的合格团队 | 人工核实的付款台账 |
| 决定等待时间 | 决定时间减该版发布时间；中位数及p90 | 只统计已决定版本，另列尚未决定数量 |
| 支持负担 | 每团队每月客服分钟数 | 工单计时，不以消息条数代替 |

内部演示、测试空间和关联付款全部排除。观察窗未结束写“未成熟”，不能计成零。北极星指标不以一个团队反复创建测试决定刷量。

## 事件字典

最小业务事件为 project_created、version_published、review_verified、comment_created、decision_created、receipt_exported、project_archived、deletion_requested。共有属性只含 event_id、workspace_id、对象 ID、actor_kind、UTC 时间、schema_version；不得包含正文。业务事件由事务 outbox 产生，event_id 去重。

## 运行指标与告警

| 指标 | 试点阈值／触发 | 动作 |
|---|---|---|
| API 5xx | 5分钟超过2%，且样本至少100；低流量连续3次探活失败另触发 | 运维看部署、依赖与错误类型 |
| 非上传 API 延迟 | 连续10分钟p95超过800ms | 检查数据库锁、慢请求和连接数 |
| 文件检查排队 | 最老待处理超过5分钟 | 检查 Worker/扫描器，不自动放行文件 |
| OTP 邮件 | 投递失败连续5次或队列超过2分钟 | 检查供应商和发送域名；暂停扩大试点 |
| 配额／磁盘 | 70%预警、85%处理 | 扩容或清理合法过期数据 |
| 备份 | 数据库可恢复点落后15分钟、完整业务恢复点超过24小时，或备份任务失败 | 立即排查，未解决停止新发布上线 |
| 数据一致性 | 任一重复决定、跨空间引用 | 高优先级事故，冻结受影响写入口 |

## 日志

结构化日志包含 request_id、route 名称、状态、耗时、错误码、匿名身份 ID、目标 ID；不要记录请求完整 URL、Cookie、Authorization、验证码、文件正文或签名参数。应用诊断日志初始计划保留14天；安全审计和接入日志的具体保存期限由上线合规核验确定，不把14天套用于所有法定日志。

产品仪表盘首版可由受控后台按业务数据汇总，不为分析另建大数据系统。每周产品与技术共同复盘指标定义和缺失情况；流量很小时直接列个案，不过度解释百分比。
