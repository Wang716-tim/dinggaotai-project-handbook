# 跨模块场景样例

使用合成空间“青禾设计”、内部 Owner O1、Editor E1、客户 reviewer@example.test，项目 P1。example.test 仅为示例，不向其发送真实邮件。ID 是文档标签，不是实际 UUID。

## 场景 A：修改后确认

M01 识别 E1 属于 W1 → M02 创建 P1 与草稿 V1 → M03 上传图片 A1 与 PDF A2，扫描成功变 READY → M02 发布并冻结清单 → M04 生成 S1，客户验证邮箱 → M04 评论绑定 V1/A1 → M05 写“需要修改”D1和记录 C1 → M07 提醒内部成员 → E1创建完整 V2并上传新文件 → 发布时撤销 S1 → 客户验证 S2并确认 → M05生成D2/C2 → M06展示当前版本已确认与v1历史。

检查：v1内容未被v2改动；旧评论不自动迁移；C1和C2分别对应各自清单；项目当前状态来自V2；原件摘要和记录摘要匹配。

## 场景 B：新版发布与旧版决定同时发生

请求甲发布V2，请求乙确认V1。两者都锁P1。若甲先提交，乙重验发现V1撤回/分享无效，返回状态错误，不能写决定。若乙先提交，V1保持历史APPROVED，甲随后发布V2并撤销旧分享，项目当前显示V2待确认。不能出现V2继承V1确认。

## 场景 C：决定提交后网络断开

数据库已提交D1但客户没收到响应。客户端用相同幂等键查询或重试；服务返回原D1和C1。若客户端错误产生新键，版本唯一约束仍避免第二条决定，并返回ALREADY_DECIDED及允许读取的原决定摘要。邮件可能被重复尝试，站内通知只一条。

## 场景 D：删除与客户访问并发

Owner请求删除P1，事务内置DELETION_PENDING并撤销S1。后续客户读写均拒绝；已签发60秒URL可能仍可使用，界面说明这一边界。Owner在7天内撤回删除后，项目恢复但S1不复活。重新发链接才能再次访问仍允许审阅的版本。

## 场景 E：配额与上传异常

剩余可用空间30MiB，两个请求各申报20MiB图片，含衍生预留后每个22MiB。空间锁保证仅一个获得预留，另一个返回额度不足。首请求传输中断，完整状态未提交，清理确认后释放预留及残留。不可因为客户端关闭页面直接认定对象已不存在。

## 场景 F：授权错误与通知失败

W2成员使用A1 ID，返回404；客户S1尝试访问V2附件，拒绝；扫描器不可用时新文件停留待处理且不能发布；邮件服务失败时已成功决定依然存在，任务重试可见。所有情况都有request_id用于排查，日志没有原始凭据。

这些场景是联调基线，测试团队应以实际服务和数据库验证。页面演示、模拟API和手工改数据库不能作为通过证据。
