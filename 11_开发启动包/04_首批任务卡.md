- 每张卡的角色需在领取时落实为一名负责人和独立验收人，并填实际阶段、冻结契约版本、执行路径、验收窗口和交接日期。此时把[项目速览](../00_协作入口/01_项目速览.md)、[全局约束](../00_协作入口/04_术语与全局约束.md)、该卡的必读内容及上一份交接单组成最小上下文。模块共享契约、迁移依赖或目录有争议时，由总负责人定案。

## T01-C · 冻结契约和环境基线

- **责任 / 范围**　技术负责人主执，产品、前端与测试复核。R01—R16。只写 T01 环境记录、模式和契约变更提案。公共契约由总负责人合并。
- **输入 / 编排**　V03/GATE-A 支持继续且已获阶段放行。读[技术总览](../02_开发手册/00_技术总览.md)、[研发流程](../02_开发手册/04_研发流程与环境.md)、[数据模型](../02_开发手册/01_数据模型.md)、[API](../02_开发手册/02_API契约.md)、[权限](../02_开发手册/03_权限与安全.md)和[请求样例](02_请求响应与错误样例.md#待定设计)。与 T01-S 共享隔离环境选定条件。
- **输出 / 验收**　提交兼容性实测与依赖锁定依据、正式接口模式、错误和空值规则、Receipt 编码与摘要、锁顺序和任务领取协议、T01-S 的环境及取证条件。用两轮主线及断网、只读、撤销等负例走读，校对模式与权限表。差异必须有所有相关消费方的结论。
- **回退 / 交接**　发现环境不兼容或契约分歧时保留可复现证据，评审通过后重新冻结。向 B01、B06、F01/F02、Q01 发已冻结模式和变更记录，向 T01-S 发环境及写入协议。实施安排仍需总负责人按 T01 适用的门槛逐项放行。

## T01-S · 存储终结取证和试验参数

- **责任 / 范围**　技术负责人主执，运维协同，测试复核。R04/R14/R16。只写隔离试验记录、终结证据和采购/技术变更提案。按阶段授权使用测试资源。
- **输入 / 编排**　V03/GATE-A 与 T01 阶段放行，T01-C 交付受控环境、实际存储接口与待测协议。读[对象写入协议](../02_开发手册/07_文件写入与回收协议.md)、[技术风险实验](../10_技术风险验证方案/01_实验清单与放行门槛.md)与[测试矩阵](../04_上线与运营/01_测试与验收矩阵.md) A28/A23-b。
- **输出 / 验收**　在原件和预览两条路径分别验证 TR01、TR02。覆盖失联执行器、响应丢失、HEAD 暂空、迟到写入、能力有效窗口与可能的重放，并证明独立回收和一次结算后合法候补可唤醒。记录数据源覆盖、适用环境、配置、时限与失败备选。冻结文件吞吐、接收超时、资源阈值与运行条件。
- **回退 / 交接**　缺终结证据或隔离破坏时关停该试验写入，保留未知写入的隔离与预算台账。未取得放行的 B03 写入路径保持关闭。向 B03/B06/Q01 交已验证条件、失败分支和替代方案评审入口。

## B01 · 内部身份、空间与成员

## B06-QUEUE · 持久领取、续租和去重

- **责任 / 范围**　M07 后端主执，M03 与测试复核。R13、B03 文件任务前置。只写任务表、领取协议、调度接缝和对应测试，文件扫描、删除处理器仍由业务模块实现。

## B03-RECEIVE · 文件预留与可恢复接收

- **责任 / 范围**　M03 后端主执，测试复核。R04/R14。只写预留、原件接收、上传/附件状态读取及对应测试。
- **输入 / 编排**　T01-C、T01-S 写入路径放行、B01 空间锁、B06-QUEUE 可入队。读[M03](../03_模块工作包/M03_文件处理.md)、[文件 API](../02_开发手册/02_API契约.md#文件)及[对象写入协议](../02_开发手册/07_文件写入与回收协议.md)。
- **输出 / 验收**　关联预留、附件和写入台账，按原件及预览预算预留，完整接收后同事务结算原件并转处理预算及任务，查询返回准确的 `received_complete`。用 A05/A19/A27 证明乱序、重复 PUT、响应丢失和额度竞争下只有合法预留。超限、非法类型及跨空间请求拒绝。
- **回退 / 交接**　出现未知写入、隔离或计量异常时暂停新预留或写入，保留台账和预算，等待独立取证清理。向 B03-PROCESS 交处理任务与预算，向 F01 交接收超时、状态查询和界面恢复证据，向 B02 提供 READY 读取契约。

## B03-PROCESS · 扫描、预览、签发与回收

- **责任 / 范围**　M03 后端主执，运维与测试复核。R04/R14，支撑 R12/R16。只写扫描、处理代际、受控下载、物理清理与占用结算。项目删除入口由 B02-LIFECYCLE 持有。
- **输入 / 编排**　T01-S、B01、B06-QUEUE 及 B03-RECEIVE。读[M03](../03_模块工作包/M03_文件处理.md)、[对象写入协议](../02_开发手册/07_文件写入与回收协议.md)、[TR02/TR03](../10_技术风险验证方案/02_实验步骤与证据记录.md#tr02--未知写入终结取证与清理重放)和[权限](../02_开发手册/03_权限与安全.md)。
- **输出 / 验收**　提供 JPEG/PNG 重编码预览、PDF 原件下载、扫描终态、所有附件 READY 判定、旧代回收、受控重试及物理清理记录。A05/A06/A19/A27/A28/A30 验收失败和迟到分支、锁与预算、过期接收已结算和未知写入保账。扫描失败无下载。完成取证清理后只结算一次，项目清理需有效删除代际。
- **回退 / 交接**　发现绕过扫描或提前释放即停相关消费者和签发，保留历史引用与取证台账。向 B02 交真实 READY 和清理接口，向 B04 交授权后附件下载能力，向 Q01 交故障观测点。
