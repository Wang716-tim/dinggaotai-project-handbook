# 开发启动顺序与交接边界

v1.3 开发准备材料，API 路径沿用 `/api/v1`。动态阶段、任务状态及负责人以[项目状态](../06_项目总控/01_项目状态.md)和[任务看板](../06_项目总控/02_任务看板.md)为准。本包用于后续执行前的接口对齐、样例评审和任务分派。当前真实验证证据尚缺，GATE-A、T01 和实施任务等待对应放行。A01—A32 及子项仍未执行。

## 放行顺序

| 阶段 | 开始条件 | 退出证据与后继 |
|---|---|---|
| 需求验证 V01 → V02 → V03 | 适格真实参与者和经授权的验证安排 | 按 [GATE-A](../07_需求验证执行包/04_GATE-A评审单.md) 核对 10 次访谈及 5 次试演的匿名原始记录、达到原有阈值并由产品与技术角色形成继续结论，才安排 T01。真实证据不足时继续等待，未达阈值按 GATE-A 评审结论处理。 |
| 技术准备 T01 | V03 结论支持继续且总负责人完成阶段放行 | 记录 Python、Django、DRF、PostgreSQL 与目标环境实测，锁定依赖和构建基线。前端、后端、测试共同冻结模型、权限、API 正式模式与样例。为文件测试、性能、浏览器及恢复要求记录环境、验证条件、证据和遗留项。 |
| T01 存储路径专门验收 | 使用受控测试存储与合成文件 | 按[文件写入与回收协议](../02_开发手册/07_文件写入与回收协议.md)实测响应丢失、执行者失联、迟到写入和独立回收，保存可核验的写入终结证据，按 [TR01/TR02 门槛](../10_技术风险验证方案/01_实验清单与放行门槛.md#阶段门槛)验收。缺少证据时登记阻塞和适配评审，B03 写入路径等待放行。 |
| 首批实施 | 依赖与卡片均具备，负责人和审核角色明确，已获阶段放行 | B01 身份与空间，B06 的队列基础，B03 文件状态与写入，B02 项目/草稿，B04 授权基础，B02 发布，B04 审阅，B05 决定与记录。F01/F02 按冻结契约可先接模拟，Q01 贯穿开发。细分路径见[首批任务卡](04_首批任务卡.md)。 |
| 后续联调与发布准备 | 原任务依赖逐项满足 | B06 通知消费、F03 历史/设置和异常、O01 环境及恢复按[原任务依赖](../01_项目手册/08_任务拆解与依赖.md)推进。Q02 验证真实服务组合，O02-PRE 汇总预发布证据，O02-RELEASE 另需公开前置与用户发布确认。 |

## 模块交接点

| 提供方 → 接收方 | 交接物与核对条件 |
|---|---|
| B01 → B02/B03/B04 | 内部成员、空间与服务状态的可信上下文，固定的工作空间锁入口。身份、角色与到期边界可在事务中复核。 |
| T01/B06 基础 → B03 | 领取、续租、代际、确认与去重约定。文件任务所需基础随 B03 接通，通知消费可独立完成。 |
| B03 → B02/B04 | READY 附件状态、顺序及原件元数据，附空间、版本及文件归属检查。B02 可依冻结接口设计项目及草稿，发布联调需接入真实状态。 |
| B02 ↔ B04 | 发布事务与分享创建、撤销的边界。B02-CORE 提供项目和版本状态，B04-GRANT 提供可加入事务的原子授权操作。B02-PUBLISH 按空间、项目、版本、分享锁顺序一并提交。随后 B04-ENTRY 消费实际发布结果。 |
| B02/B04 → B05 | 当前发布版、有效客户会话、评论边界与授权校验，决定时在事务内复核。B05 提供决定、记录读取与通知事件引用供接收方联调。 |
| 后端 → F01/F02/Q01 | 正式接口模式、动作权限、竞态预期和错误样例，配合[请求响应](02_请求响应与错误样例.md)与[页面接口映射](03_合成数据与页面接口映射.md)。记录模拟环境与真实服务的差异。 |

## 切换上下文与证据

领取时提供[项目速览](../00_协作入口/01_项目速览.md)、[全局约束](../00_协作入口/04_术语与全局约束.md)、一张任务卡、本模块工作包、直接消费的契约节选和最近一份交接单。按[隔离与交接规范](../00_协作入口/03_上下文隔离与交接规范.md)先复述结果、输入输出和三个不变量。独立上下文只写任务卡划定的模块。跨模块变更提出影响和验证方法，由总负责人组织公共契约合并。未冻结结构在[待定设计](02_请求响应与错误样例.md#待定设计)登记。

用[交接单](../05_协作模板/02_交接单.md)记录任务 ID、冻结的契约版本、实际负责人、改动路径、可打开证据、失败分支、剩余风险和下一步。阶段状态写回项目总控。模拟页面交付可记录样例、页面截图和交互结果。真实联调需记录实际构建、环境、执行时间、执行人、服务端请求标识和失败恢复证据。身份、发布、决定、删除涉及权限或并发时，证据应包含真实 PostgreSQL 数据结果。文件和恢复路径按对应协议取证。缺证据的产品用例保留未执行。
