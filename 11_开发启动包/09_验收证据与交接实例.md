# 验收证据与交接实例

v1.5 · 2026-11-25。领取前由[启动顺序](01_启动顺序与交接边界.md)核对放行条件，再用[需求到验收追踪表](05_需求到验收追踪表.md)定位任务、契约和用例。项目阶段及任务状态以[项目状态](../06_项目总控/01_项目状态.md)和[任务看板](../06_项目总控/02_任务看板.md)为准。

## 组织与签收证据包

1. **领取时定范围。** 在[任务卡](../05_协作模板/01_任务卡.md)写明现有任务、R、A 或 TR 编号，明确必验分支、前置、执行人、独立复核人及直接消费者。文档审校沿用 [05 审校记录](../05_协作模板/05_文档审校记录.md)的检查口径；实验逐分支填写[实验记录](../10_技术风险验证方案/02_实验步骤与证据记录.md#单分支证据记录模板)；产品测试逐主项和子项引用[验收矩阵](../04_上线与运营/01_测试与验收矩阵.md)断言。
2. **按一次运行组织。** 获准执行后，在团队指定的受控位置建立 `任务ID/运行号/`，以 `索引` 指向 `输入`、`原始结果`、`脱敏复核件` 和 `交接单`。这些是建议的归档名称，目前尚无应用目录。用现有编号识别每个分支，运行号关联本次输入与结果。记录合成夹具版本或摘要、初始状态、步骤及触发证明、预期和实测、关联标识及 UTC 起止时间。复跑另建运行号，引用首次偏差和旧构建，保留可复验的首次结果。
3. **绑定版本与环境。** 文档检查记录固定提交或发布包指纹及实际检查范围。运行证据记录应用提交、构建或配置摘要、依赖和迁移版本，以及实际测试环境及影响断言的参数。适用时记录数据库版本、存储区域和接口、浏览器及固定时钟设置。模拟和真实联调各记一笔，注明覆盖的断言。权限、并发、文件和恢复等断言随对应契约保存服务端、数据库、存储或恢复的原始观测，截图作为界面证据。
4. **先核权限，再交付。** GitHub 文档仓库为公开仓库。原件、原始日志及个人信息留在各自获准的受控位置，凭据留在凭据管理环境。交接单指向授权工单或受控证据位置，登记保管人、可读角色、匿名关联标识及脱敏范围。公开包仅放审校后的文档、合成样例和获准公开的摘要，移除真实客户原件、真实邮箱、有效验证码、Cookie、密钥、签名 URL 及内部证据地址；明确标记的合成样例可保留。获准执行的匿名访谈、试演事实填入 [07 证据记录与评分表](../07_需求验证执行包/03_证据记录与评分表.md)，合成例留在演示和测试材料中。
5. **让接收者复验。** 按[交接单](../05_协作模板/02_交接单.md)交齐变更路径、冻结契约、可读证据、下游消费者、遗留项的影响和处理责任。独立复核人用索引打开受控证据，核对构建、环境与覆盖范围，至少回查关键正反断言至对应输入和原始观测，记录复核日期、范围、结论及待补项。实验按[放行门槛](../10_技术风险验证方案/01_实验清单与放行门槛.md#判定与取证)记判定；产品结果按验收矩阵登记。交接单提供引用，实际阶段及任务变更由总负责人写入 06。
