# 部署与发布手册

这里描述将来执行的流程，不包含部署脚本，也不表示已购资源或已上线。

## 部署方案

主方案为中国大陆单地域部署，应用与数据库、对象存储靠近，使用已落实手续的运营主体和域名。部署地域是服务与数据处理决策，不因备案等待而自动换境外。若改地域，重新评估访问质量、数据跨境、供应商条款及隐私告知。

首版：一个应用实例、受限扫描Worker（可在独立实例运行）、托管PostgreSQL、私有对象桶、独立文件域名、邮件服务、探活和告警。应用单点故障可能导致中断；不对外承诺多活或高可用SLA。

## 公开访问前置清单

| 项目 | 责任 | 需要的证据 |
|---|---|---|
| 主体与收费资格、业务分类 | 运营 | 适用要求核验记录；需要时取得专业意见 |
| 域名、接入备案及其他适用手续 | 运营/运维 | 服务商核验结果与完成证明 |
| 应用与文件域名HTTPS | 运维 | 证书、自动续期及到期告警验证 |
| OSS访问方式 | 运维 | 所选地区/账号的域名要求、私有读写及下载实测 |
| 隐私说明、服务条款、删除渠道 | 产品/运营 | 可访问页面、版本、联系渠道 |
| 邮箱发信 | 运维 | 供应商验证、域名认证与目标邮箱送达测试 |
| 备份、恢复与值班 | 运维 | 实际演练记录、告警接收人 |
| 收款与凭证 | 运营 | 真实收费前可用的合法收款、开票或凭证流程 |

国内互联网信息服务涉及许可/备案等制度，具体适用性按实际业务核验，不把“收费”简单等同某一许可结论，也不宣称备案覆盖全部要求。[工信部管理办法](https://www.miit.gov.cn/datainfo/fgk/gytxyxxhfg/xzfg/art/2020/art_44595811ff9a42b9b073386046905103.html)。

本次接管时上表所有事项均为“未核实”，证据位置为空，不默认已完成。总负责人在D01逐项分配实际执行人，更新状态、证据和阻塞对象；前七项阻塞公开服务，收款与凭证还阻塞收费。没有主体资料时可以完成核验清单，不能代填主体或假称取得许可。

## 环境准备顺序

完成资源预算与采购 → 设置独立生产网络和最小权限 → 配置托管数据库备份 → 建私有桶及生命周期 → 验证域名与HTTPS → 部署应用/Worker并注入密钥 → 连接邮件与告警 → 导入仅有管理员的初始配置 → 执行合成样本闭环。生产不导入本地测试客户数据。

发布前检查DEBUG关闭、可信主机/Origin收紧、Cookie/CSRF配置、请求体限制、上传超时、后台访问保护、容器权限、磁盘监控和依赖补丁。正式参数由T01和压测结果确定，不能复制示例值后跳过验证。

## 一次发布

1. 记录构建版本、变更范围、迁移影响和回滚版本，确认四方验收结论。
2. 检查最新备份与完整业务恢复点；有破坏性迁移则另设维护窗口。
3. 在预发布执行同一产物和迁移，完成关键流程；禁止生产临时改包。
4. 生产应用兼容迁移，短时停写或切维护模式，按已演练顺序更新应用与Worker。
5. 检查探活、任务领取和错误率；内部合成项目完成上传、验证、决定、导出。
6. 开放首批1家，再到5家，观察至少一个工作日；记录实际结果。

## 回滚条件与动作

发现越权、错误版本确认、核心数据损坏、持续核心流程失败，立即冻结受影响入口。后续版本的普通应用故障可切回上一已验证产物；首次发布若没有上一产物，执行已演练的关闭公开入口/维护页、停写和保留现场，不能引用不存在的旧版本。数据库保持向后兼容，不盲目反向执行破坏性迁移；已写错数据需独立核对修复。

O02-PRE在预发布先产出上述演练证据、权限/恢复检查及四方放行包，再允许O02-RELEASE请求用户具体确认公开。首次发布演练至少验证关闭入口后无新写、后台清理及取证可控、恢复入口前核心合成流程重新通过；不是只展示一张维护页。

新版本5xx连续5分钟超过2%且有效样本至少100时调查并按影响回滚；低流量连续3次核心合成检查失败同样触发。撤回发布不等于撤销客户已经形成的业务决定。

公开试点条件未齐时只允许合规的内部测试环境，研发验收结束可交付可部署版本并等待上线门槛；之后才启动真实试点观察窗口，不能把尚未获准公开访问的服务称为已上线。
