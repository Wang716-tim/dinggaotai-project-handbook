# M01｜账号与团队

负责人：后端；协作：前端、运营；任务 B01；需求 R01/R02/R15。

## 最小上下文

必读 [全局约束](../00_协作入口/04_术语与全局约束.md)、[权限矩阵](../02_开发手册/03_权限与安全.md)、[数据模型](../02_开发手册/01_数据模型.md) 的身份部分、[API](../02_开发手册/02_API契约.md) 的身份部分。无需加载文件扫描和导出实现细节。

## 负责与边界

负责邮箱登录、内部会话、空间状态、Owner/Editor、邀请、成员移除、配额配置与受控运营开通。为其他领域提供可信成员上下文和空间写入能力判断。客户验证的通用验证码服务由本模块提供，客户授权语义由M04决定。

不负责项目内容权限状态、不代替M04签发客户授权、不允许运营管理员默认浏览客户文件。前端页面由M06实现。

## 输入输出与规则

输入为经CSRF保护的邮箱挑战与验证码、Owner成员管理请求；输出是内部会话、空间、角色和能力。User身份不等于有效Membership；每次业务请求重新检查成员有效性，避免移除后旧Cookie继续访问。

工作空间到期进入READ_ONLY；冻结进入SUSPENDED。服务能力返回明确的read/write/review可用性与原因，各模块必须消费，不自行推测到期时间。到期只读保留导出；冻结拒绝客户业务访问，注销仍按权威权限表执行。

能力服务依据service_state和服务端时间相对expires_at共同判定，不等待过期Worker更新才禁写。验证、下载签发及清理虽可能使用POST或更新技术字段，仍按公共服务状态动作表处理。邀请摘要仅用于校验，异步邮件的原始密钥由短期加密投递信封提供，不在普通任务载荷保存。

邀请先预占席位，接受、取消和过期在空间锁下更新；禁止两个并发邀请越过5席位。Owner转让不在自助首版范围，如有必要经核验身份的支持流程处理，不能直接删除唯一Owner。

## 实施顺序

定义空间与成员约束 → OTP用途隔离和限流 → 会话/CSRF → 邀请接收 → 移除即时失效 → 只读/冻结能力 → 限权运营后台及审计。OTP邮件发送依赖M07，投递失败返回中性提示并保留可诊断状态。

## 必须通过

未受邀邮箱无法创建业务空间；重复验证码只能消费一次；旧码作废；邀请与登录邮箱不匹配失败；移除后旧会话无效；Editor不能管成员；并发邀请不超额；冻结后客户不能访问；到期后仍可内部导出但不能决定；同一账号不能加入第二个空间。

交付：身份契约实现、迁移说明、角色/限流测试、运营操作审计证据和交接单。不得交付生产密钥或真实用户邮箱列表。

受控运营的开通、续期和冻结按[操作规格](../02_开发手册/08_受控运营操作规格.md)评审；后台权限不能等同于默认全表编辑。首次Owner核验和后台传输模式仍待T01，普通邀请只能产生Editor。现有48项公开业务API不因此扩充，应用和运营操作均未实现。
